# Правила проекта

Это статический многостраничный сайт **kushnarenko.net**: сборка Vite + Pug + SCSS + ванильный JavaScript. Бэкенда нет — результат прод-сборки это статические файлы в `build/`.

**Репозиторий:** [Dennchik/Kushnarenko.net](https://github.com/Dennchik/Kushnarenko.net) (GitHub, ветка `main`, владелец — Dennchik)

**Стек:**

- **Сборка:** Vite 7 — MPA, `base: './'`, выход в `build/`, минификация esbuild, разделение vendor-библиотек на chunks (`vite.config.js` + конфиги в `vite/config/`, задачи в `vite/tasks/`)
- **Шаблоны:** Pug 3 — страницы в `pages/*.pug`, компоненты/лэйауты в `src/pug/`; плагин `@mish.dev/vite-convert-pug-in-html`
- **Стили:** SCSS (sass) + PostCSS: `autoprefixer`, `postcss-media-minmax`, `postcss-sort-media-queries` (только в прод-сборке)
- **JavaScript:** ванильные ES-модули; алиас `@` → `src/`
- **Ассеты:** `sharp` — конвертация изображений в WebP; `ttf2woff` / `ttf2woff2` — конвертация шрифтов
- **Качество кода:** ESLint 9 (flat config `eslint.config.js`), Prettier 3 (`.prettierrc`), Stylelint 16 (`.stylelintrc.json`: плагины `stylelint-selector-bem-pattern`, `stylelint-config-clean-order`)
- **Библиотеки (runtime):** Swiper, GSAP, imask, nouislider + wnumb, @fancyapps/ui

## Graphify MCP

- Этот проект проиндексирован в Graphify: репозиторий **Dennchik/Kushnarenko.net** (repository_id `1a9219a6-5cc1-477a-8787-408ad9ffe3e2`), ~500 узлов кода.
- Индекс обновляется автоматически при каждом push в GitHub; результаты отражают последний проиндексированный коммит.
- Доступно через MCP-инструменты: поиск символов (`search`, `graphify_find`), вопросы по коду (`query_graph`), трассировка вызовов (`graphify_trace`), соседи файла/зависимости (`graphify_file_neighbors`, `graphify_imports_exports`), callers (`graphify_callers`), оценка влияния изменений (`graphify_impact`).
- Перед правками кода можно проверять затронутые места через `graphify_impact`; долгоживущие решения и gotchas проекта сохранять через `remember`.

## Команды:

- Разработка: `npm run dev` — единственный процесс: Vite dev-сервер (порт 5173, HMR) компилирует Pug-страницы и отдаёт их вместе с JS/SCSS; браузер открывается автоматически (`server.open: true`)
- Прод-сборка: `npm run build` (= `vite build`, выход в `build/`)
- Предпросмотр прод-сборки: `npm run preview` (порт 4173)

## Ограничения:

- Две точки входа JS обязательны: `src/js/main.js` и `src/js/app.js` (прописаны в `rollupOptions.input` в `vite.config.js`) — не удалять и не переименовывать без правки конфига.
- Новые страницы добавлять как `pages/<имя>.pug`; их части — в `src/pug/`.
- Кастомную логику сборки добавлять задачами в `vite/tasks/`, конфигурацию — в `vite/config/`, не раздувая `vite.config.js`.

## Стандарты:

- JavaScript и SCSS форматируются Prettier/Stylelint; конфиг: `.prettierrc` (отступ 2 пробела, одинарные кавычки, длина строки 80), `.stylelintrc.json`. Линтинг JS — ESLint 9 (flat config `eslint.config.js`).
- Структура JS: точки входа `src/js/main.js` и `src/js/app.js`; страничные и переиспользуемые модули — `src/js/modules/`, компоненты — `src/js/components/`, лэйауты — `src/js/layouts/`, анимации — `src/js/animations/`, роутинг — `src/js/router/`, утилиты — `src/js/utils/`, библиотечные обёртки — `src/js/libraries/`, ассеты — `src/js/assets/`.
- Структура SCSS: `src/scss/core/` (базовые стили), `src/scss/components/`, `src/scss/layouts/`, `src/scss/pages/`, `src/scss/sections/`, `src/scss/modules/`, `src/scss/utils/`, `src/scss/chunks/`, `src/scss/assets/`.
- Структура Pug: страницы — `pages/*.pug`; лэйауты — `src/pug/layouts/`, секции — `src/pug/sections/`, модули — `src/pug/modules/`, включения — `src/pug/includes/`, чанки — `src/pug/chunks/`, утилиты — `src/pug/utils/`.
- В JavaScript при создании имён переменных и функций используй принцип camelCase (верблюжий регистр). Исключение: константы уровня модуля — `SCREAMING_SNAKE_CASE` (например, `AJAX_HEADERS`, `STORAGE_PREFIX`).
- В SCSS используй BEM-нотацию. Для элементов применяй вложенность с оператором `&`.

**🎨 Стили (SCSS)**

**BEM-нотация**

  - Для элементов блока используй `&__element`.
  - Всегда отделяй комментарием селектор, если он генерируется через `&`.

***Шаблон для элемента:***

```scss
.block-name {
	// .block-name__element
	&__element {
		// свойства
	}
}
```

***Модификаторы BEM (SCSS)***

- Модификатор элемента вкладывай внутрь `&__element`, модификатор блока — внутрь самого блока.
- В HTML модификатор всегда идёт вместе с базовым классом.
- В модификаторе указывай **только отличия** от базового элемента.
- Перед `{` ставь пробел. Пустое тело модификатора запрещено.

**Шаблон:**

```scss
.block-name {
	// .block-name__element
	&__element {
		// базовые свойства

		// .block-name__element--modifier
		&--modifier {
			// только отличия
		}
	}
}
```

## Исключения: папки, которые НЕ индексировать

Следующие директории являются исключениями. Не сканируй их, не индексируй, не предлагай изменения в файлах внутри них и не включай их содержимое в анализ контекста:

- `node_modules/`
- `dist/`
- `build/`
- `temp/`
- `coverage/`
- `.cache/`
- `tmp/`
- `logs/`

**Правила работы с исключениями:**

- Обращайся к этим папкам **только по прямому указанию** пользователя (например: «посмотри, что лежит в `node_modules/foo`», «проверь `build/assets`»).
- Без явного указания считай, что этих папок не существует: не читай их, не ищи в них, не ссылайся на их содержимое.
- Если пользователь просит внести изменения в код, а решение требует правки файла в исключённой папке — **остановись и уточни**, нужно ли это делать, вместо того чтобы менять файл самостоятельно.
- Не предлагай «почистить» или «обновить» исключённые папки по своей инициативе.

**Важно:** папка `vite/` НЕ является исключением — это собственный код сборки проекта (`vite/config/`, `vite/tasks/`, `vite/utils/`), её нужно читать и индексировать наравне с `src/`.

## Запрещено:

- Плодить вложенность вида `&__element__sub-element`.
- Оставлять селектор без тела правила (пустой `{}`).
- Оставлять неиспользуемые файлы, импорты и закомментированный код после рефакторинга.
- Коммитить `.env`, `node_modules/`.
- Добавлять `build/` в `.gitignore`: папка `build/` коммитится **намеренно** — это финальная сборка, которая передаётся бэкенд-разработчику для дальнейшей работы.

## Безопасность:

- Никогда не пиши API-ключи, токены или пароли в коде.
- `.env` не читай без необходимости и никогда не включай его содержимое в ответы и коммиты.

## Git:

- Коммиты — короткие, осмысленные, на русском; без «update» и даты в сообщении.
- Не делать `git push` и не коммитить без явной просьбы пользователя.
